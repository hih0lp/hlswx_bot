# Патч для Hammer / W: две недостающие ручки интеграции

Что закрывает: ТЗ 6.6 (тишина группы после разового поста) и ТЗ 6.8 (кнопки
«Редактировать» и «Закрыть» на опубликованных постах).

Файл: `hammer_hwls_integration.patch` — четыре файла в проекте `hammer-bot`,
из них один новый.

## Зачем это нужно на стороне Hammer

Оба изменения обязаны жить именно здесь, потому что Telegram не оставляет
выбора:

- **бот не видит сообщений других ботов.** Даже добавленный во все группы
  администратором, основной бот не узнает о разовых постах Hammer. Поэтому
  факт публикации ему надо сообщить явно;
- **бот может редактировать только свои сообщения.** Пост в группе отправлен
  ботом Hammer/W, значит и править его может только он. Кнопка в основном
  боте способна лишь попросить.

## Состав

| Файл | Изменение |
|---|---|
| `app/services/hwls_notify.py` | новый: исходящий вызов `POST /api/hwls/oneshot-published` |
| `app/services/publisher.py` | +18 строк: вызов уведомления после публикации разового поста |
| `app/config.py` | +3 строки: настройка `HWLS_ONESHOT_WEBHOOK_URL` |
| `app/api/hwls_routes.py` | +136 строк: ручки `POST /api/hwls/edit` и `POST /api/hwls/close` |

## Что важно при приёмке

**Патч ничего не меняет, пока его не включат.** `HWLS_ONESHOT_WEBHOOK_URL`
по умолчанию пуст — уведомление не отправляется, поведение публикации
остаётся прежним. Новые ручки просто добавляются к существующему роутеру и
авторизуются тем же `X-HWLS-Key`, что и `/api/hwls/publish`.

**Сбой уведомления не ломает публикацию.** Вызов обёрнут в `try/except`:
пост уже в группе, и откатывать его из-за недоступности соседнего сервиса
нельзя. Худшее последствие недоступности — не наступит тишина, то есть
поведение вернётся к сегодняшнему.

**Правка перерисовывает пост тем же `render_ad_publication`,** что и
публикация, поэтому вёрстка, подпись контакта и спонсорский футер
сохраняются. Закрытие оборачивает текст объявления в `<s>`. Посты с
фотографией правятся через `edit_message_caption` — у них не текст,
а подпись.

## Применение

На сервере нет git и `/opt/hammer-bot` не является репозиторием, поэтому
применяем `patch`, а не `git apply`. Флаг `-b -z` оставляет рядом копию
каждого изменённого файла — этого достаточно для отката вручную.

```bash
cd /opt/hammer-bot
patch -p1 --dry-run < hammer_hwls_integration.patch   # проверка без изменений
patch -p1 -b -z .prepatch < hammer_hwls_integration.patch
echo 'HWLS_ONESHOT_WEBHOOK_URL=http://127.0.0.1:8082/api/hwls/oneshot-published' >> .env
docker compose up -d --build
```

Порт 8082 — основной бот на том же хосте; у `bot_app` сетевой режим `host`,
так что адрес доступен без проброса портов. Секрет `HWLS_RELAY_SECRET` уже
общий и менять его не нужно.

Учтите, что `.env` читают оба сервиса, поэтому `docker compose up -d`
пересоздаст и контейнер БД. Данные лежат в томе `postgres_data` и не
теряются, но перерыв в работе будет не только у приложения.

Откат: `patch -p1 -R < hammer_hwls_integration.patch`, либо просто убрать
`HWLS_ONESHOT_WEBHOOK_URL` из `.env` — второго достаточно, чтобы вернуть
прежнее поведение без раскатки кода назад.

## Как это проверялось

Патч не написан «по документации» — он собран и прогнан на копии Hammer,
поднятой рядом с боевой (`/opt/hammer-test`, порт 8001, тестовые боты
@HammerTestingbot и @WwwwwTestingbot, тестовые группы). Проверено:

- публикация через релей: пост выходит, `message_id` возвращается;
- правка: текст меняется в группе, `HWLS edit applied … 200 OK`;
- закрытие: объявление зачёркивается, `HWLS close applied … 200 OK`;
- уведомление о разовом посте: тишина встаёт на 20 минут вперёд, только
  в нужной группе;
- идемпотентность: повторный вызов с тем же `message_id` окно не сдвигает,
  в журнале одна запись.
