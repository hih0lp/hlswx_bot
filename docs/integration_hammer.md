# Интеграция основного бота с Hammer / W

Документ для разработчика ботов **Hammer** и **W**. Описывает, что нужно вызвать на
стороне основного бота (HWLS), чтобы выполнялись требования ТЗ 6.6 и 6.8.

Все запросы авторизуются заголовком `X-HWLS-Key` с общим секретом
(`HWLS_RELAY_SECRET` — тот же, что уже используется для исходящей публикации).

Базовый адрес: `http://<хост-hwls>:8082`

---

## 1. Разовый пост вышел в группе → тишина 20 минут

**Обязательно для приёмки.** Без этого вызова основной бот не знает о разовых постах,
и 20-минутная тишина в группе не наступает.

```
POST /api/hwls/oneshot-published
X-HWLS-Key: <секрет>
Content-Type: application/json
```

```json
{
  "telegram_chat_id": -1003031021884,
  "telegram_username": "Work77Hammer",
  "network": "hammer",
  "message_id": 12345,
  "published_at": "2026-09-04T12:00:00Z"
}
```

| Поле | Обязательно | Описание |
|------|-------------|----------|
| `telegram_chat_id` | да, если нет `telegram_username` | ID группы в Telegram |
| `telegram_username` | да, если нет `telegram_chat_id` | Публичный username группы, с `@` или без |
| `network` | нет | `hammer` или `w`, по умолчанию `hammer` |
| `message_id` | желательно | ID опубликованного сообщения; нужен для защиты от повторов |
| `published_at` | нет | Время выхода поста в ISO 8601; по умолчанию — момент запроса |

Ответ:

```json
{ "ok": true, "duplicate": false, "chat_id": 1, "chat_title": "Работа Москва",
  "silence_until": "2026-09-04T12:20:00+00:00" }
```

Поведение основного бота:

- окно тишины ставится **на 20 минут вперёд от `published_at`**, безусловно —
  каждый новый разовый пост пересчитывает его заново, даже если группа уже в тишине;
- посты подписчиков и белого списка, ждущие эту группу, не отклоняются, а переносятся
  на конец тишины;
- повторный вызов с тем же `message_id` ничего не двигает (`duplicate: true`) — запрос
  можно безопасно ретраить.

Ошибки: `401 unauthorized` (неверный секрет), `404 chat_not_found` (группы нет в базе
основного бота), `400` при некорректном теле запроса.

Проверка:

```bash
curl -X POST http://127.0.0.1:8082/api/hwls/oneshot-published \
  -H 'X-HWLS-Key: <секрет>' -H 'Content-Type: application/json' \
  -d '{"telegram_chat_id":-1003031021884,"network":"hammer","message_id":1}'
```

## 2. Правка и закрытие опубликованного поста

**Нужно реализовать на стороне Hammer / W.** Посты, ушедшие через релей, публикует
бот-партнёр, поэтому основной бот не может их редактировать сам. Кнопки
«Редактировать» и «Закрыть» (ТЗ 6.8) для таких постов заработают, когда появятся
две ручки. Клиент к ним в основном боте уже написан и включается настройкой
`HAMMER_RELAY_EDIT_ENABLED=true`.

```
POST /api/hwls/edit
POST /api/hwls/close
X-HWLS-Key: <секрет>
```

```json
{
  "telegram_chat_id": -1003031021884,
  "message_id": 12345,
  "text": "новый текст объявления",
  "contact": "@username",
  "network": "hammer"
}
```

Ожидаемый ответ: `{"ok": true}` либо `{"ok": false, "error": "..."}`.

- `/api/hwls/edit` — заменить текст сообщения;
- `/api/hwls/close` — зачеркнуть текст объявления, пометив пост закрытым.

Пока ручек нет, основной бот правит только те посты, которые опубликовал напрямую,
а по остальным отправляет администратору задачу на ручную правку.

---

## 3. Публикация из основного бота в группы (уже работает)

Существующий исходящий вызов, приведён для полноты:

```
POST /api/hwls/publish
X-HWLS-Key: <секрет>
```

Поле `apply_chat_lock: true` означает, что пост разовый и группа должна уйти в тишину
и на стороне Hammer.

## Что нужно от заказчика для полной сдачи п.6.6

1. Реализовать вызов `POST /api/hwls/oneshot-published` в момент публикации разового
   поста в Hammer и W.
2. Реализовать `POST /api/hwls/edit` и `/api/hwls/close` для правки и закрытия постов.
3. Выдать тестовые токены ботов и 2–3 тестовые группы для проверки без влияния на
   боевых пользователей.

До выполнения п.1 тишину можно ставить вручную командой администратора
`/silence <chat_id|@username> [минут]` — механика та же самая.
