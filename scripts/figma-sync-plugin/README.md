# Плагин синхронизации макета

Переносит в рабочий макет правки, сделанные в боте. Один запуск — всё разом.

## Почему плагин, а не HTTP-скрипт

REST API Figma умеет файл только **читать**. Эндпоинта, который меняет текст
ноды, в нём нет: из записи доступны комментарии, dev-ресурсы и переменные
(последние — только на Enterprise). Менять содержимое файла может исключительно
Plugin API, то есть код, исполняемый внутри Figma.

Figma MCP делает ровно это, но через посредника, у которого на тарифе Starter
**20 вызовов в месяц**. Локальный плагин ходит в тот же Plugin API напрямую и
никаких лимитов не знает.

## Установка (один раз)

Нужно **десктопное** приложение Figma — в браузере плагины из файлов не
ставятся.

1. Открыть рабочий макет — «HLSWX Bot (Copy)», файл `6fTrkI6HhKoNap5BPPHIjr`.
2. Меню **Plugins → Development → Import plugin from manifest…**
3. Выбрать `scripts/figma-sync-plugin/manifest.json` из этого репозитория.

## Запуск

**Plugins → Development → HLSWX — синхронизация подписей.**

Откроется окно с отчётом: что изменено, что уже совпадало, что не нашлось.
Файл после этого надо сохранить как обычно (десктопная Figma сохраняет сама).

## Кнопка «Скачать дамп макета»

В том же окне. Кладёт рядом с отчётом файл `figma.json` — его надо положить в
`docs/design/figma.json`, и по нему сверяются бот с макетом:
`scripts/figma_screens.py`, `scripts/figma_buttons.py`, `scripts/figma_origin.py`
и два теста (`test_figma_parity.py`, `test_figma_buttons.py`).

Раньше дамп снимался REST-API, а для него нужен personal access token,
которого у нас нет; Figma MCP оригинал не читает вовсе, и лимит там 20 вызовов
в месяц. Получалось, что после каждого прогона плагина дамп устаревал и сверка
начинала врать: 20.09.2026 кадр `341:1248` ещё показывал расхождение, хотя в
файле его уже не было. Плагин работает внутри Figma и видит документ целиком,
так что снимает дамп сам — без токена, лимита и сети (в манифесте
`networkAccess: none`).

**Скачивайте дамп после каждого прогона, который что-то изменил.**

Две особенности:

- выгружается только страница 🎯 Flows — по ней и идут все сверки; страниц
  «Скрины», «Banner» и «Cover» в файле не будет;
- полей меньше, чем у REST-выгрузки (только то, что читают скрипты), поэтому
  файл ~0,7 МБ вместо ~3 МБ. Разбор совпадает нода в ноду — сверено
  прогоном обоих дампов через `figma_read.py`.

## Что делает

Четыре прохода по странице 🎯 Flows, все списки — в начале `code.js`.

**`EDITS` — подписи.** Кнопки, у которых в боте укоротили текст, чтобы он влез
в кнопку в половину ряда, плюс опечатка «1 час» → «1 чат» в кадре очереди:

| Было в макете | Стало |
|---|---|
| 💰 Пополнить баланс | 💰 Пополнить |
| 🏙 Города и группы | 🏙 Города и чаты |
| ➕ Подключить бота | ➕ Подключить |
| 🔎 Найти партнёра | 🔎 Найти |
| ➕ / ✅ Добавить город | ➕ / ✅ Добавить |
| 🏙 Открыть город | 🏙 Открыть |

**`DROPS` — колонка с Telegram ID.** Заказчик просил убрать цифры `19####` из
кадра «Все записи». Строка там собрана как `[#N, точка, 1904406102, точка,
@username]`, поэтому вместе с числом уходит одна точка-разделитель — иначе
осталось бы `#1 · · @username`.

**`TRIMS` — число записей на странице.** В макете их 10, в боте 8: экран уходит
подписью к баннеру, а она ограничена 1024 символами. Подпись пагинации
пересчитывается по числу записей из шапки («Всего: 61» → «1 / 8»).

Заодно проход подчищает **пустые кнопки**. Запись нарисована внутри кнопки, и
до 20.09.2026 обрезка удаляла запись, оставляя оболочку: на `338:725` так
повисли две полоски-кнопки без подписи, которые сверка рядов приняла за два
лишних ряда. Теперь оболочки без содержимого убираются всегда, а не только
когда что-то обрезали, — иначе старый мусор остался бы навсегда.

**`INSERTS` — недостающие строки и кнопки.** Там, где бот показывает больше,
чем нарисовано: строка «⏱ В очереди» на кадре `337:208`, «🚫 Истекших» на
`338:453`, кнопка «🔗 Интеграция бота» в двух кадрах профиля. Ноду не создаём с
нуля, а **клонируем соседнюю** — у клона сразу правильный шрифт, кегль, цвет и
поведение в авто-лейауте, и не повторяется история с подменой `Google Sans`.
Повторный запуск ничего не задвоит: если подпись в кадре уже есть, проход её
пропускает.

**`SPLITS` — пара кнопок по отдельным рядам.** Обратная операция к `REGROUPS`.
В половину ряда Telegram вмещает 16 знакомест, а в «⚙️ Настройки очереди» их
20, в «🔎 Найти пользователя» — 21: хвост обрежется. Кнопка уже готовый
скруглённый кадр, поэтому достаточно поднять её на уровень выше — ряд в полную
ширину получается сам собой. Опустевший горизонтальный контейнер удаляется.

**В записях `SPLITS` не указывайте `name`.** Для остальных проходов запасной
поиск кадра по имени полезен, для этого — ловушка: контейнер он же и удаляет,
а имена не уникальны. «Frame 45» носят два контейнера — `340:342` из «Оплат» и
`344:1342` из «Партнёров», где пара кнопок стоять как раз должна. После
первого прогона поиск по имени нашёл бы единственный оставшийся, счёл его
однозначным и разнёс чужую пару. Без `name` поиск вернёт null, и повторный
прогон просто напишет в отчёт «контейнер не найден».

**`ROWS` — разложить кнопки по сетке.** Появился 20.09.2026, когда понадобилось
вернуть кнопкам минут на `341:1248` сетку 2+2+1. Тремя проходами выше это не
собирается: `PAIRS` видит «3 мин» и «4 мин» в одном горизонтальном контейнере
с остальными и отчитывается «уже в одном ряду», а `SPLITS` разводит ряд целиком
и обратно уже не соберёт. `ROWS` задаёт раскладку целиком — и потому
идемпотентен: сверяет текущие ряды с нужными и при совпадении не трогает
ничего. Недостающие ряды клонирует с образца; образец берите из того же кадра,
тогда зазор, поля и режим ширины совпадут сами и `matchBox` не понадобится.

```js
{
  id: "341:1272",            // контейнер-колонка с рядами
  template: "341:1273",      // образец горизонтального ряда
  grid: [["1 мин", "2 мин"], ["3 мин", "4 мин"], ["5 мин"]],
  where: "Интервал 341:1248 — сетка минут 2+2+1",
}
```

Ширину кнопок проход не трогает: у всех режим `FILL`, и она считается от
контейнера сама — в ряду из двух по половине, в собственном ряду во всю строку.

**`PAIRS` — вернуть пару кнопок в один ряд** и **`WIDTHS` — выровнять ширину**.
Оба появились 18.09.2026 как уборка за собственной ошибкой: `SPLITS` не нашёл
свой контейнер по id (его удалил предыдущий прогон), свалился на поиск по имени
«Frame 1» — так называются десятки контейнеров — и разнёс кнопки в чужих кадрах
«Ошибка» и «Ошибка 2». `PAIRS` возвращает их обратно, клонируя уцелевший такой
же ряд; `WIDTHS` доправляет ширину кнопкам, которые подняли из ряда наверх, но
размер им не поменяли.

**Поиск кадра по имени теперь требует единственного совпадения.** Если имя
носят несколько контейнеров, проход честно отказывается работать и пишет об
этом в отчёт. Лучше не найти, чем молча починить не то.

**`COLUMNS` — раскладка колонки на холсте.** Кадры стоят колонками с постоянным
зазором, а `INSERTS` делает кадр выше — и он наезжает на соседний снизу.
Проход раскладывает колонку заново по фактическим высотам, последним из
изменяющих, и задаёт позицию абсолютно: повторный запуск не сдвигает кадры
дальше.

**Про размер перенесённой кнопки.** Ширина задаётся режимом (`FILL` / `HUG`), а
не числом, и вертикальные поля у половинной кнопки меньше, чем у полноширинной.
`SPLITS` и `REGROUPS` копируют то и другое с соседа по новому контейнеру
(`matchBox`) — без этого кнопка встаёт правильного порядка, но вдвое уже
остальных либо, наоборот, выпирает за ряд.

**`REORDERS` — перестановка строки.** Нужна там, где макет спорит сам с собой:
на `338:661` статус записи стоит последним, а на `349:1219` — сразу под именем.
Бот следует второму, проход приводит первый.

**Возврат шрифта.** Если «Google Sans» в системе не установлен, правка текста
тянет за собой подмену на «Google Sans Flex» — плагин об этом честно пишет в
отчёте. Рендерится он почти неотличимо, но с каждым прогоном файл расслаивается
сильнее: на 18.09.2026 таких нод набралось 70 из 1242. Последний проход
возвращает родное семейство, но только если шрифт доступен; иначе он ничего не
делает и просит его установить. Прогон без установленного шрифта безопасен —
просто ничего не изменится.

**`PROBES` — разведка.** Ничего не меняет, печатает строение кадра: id, тип,
имя, направление авто-лейаута и отступы. Нужна там, где правка на раскладке, а
строения кадра в локальном дампе `docs/design/figma.json` нет.

Плагин **идемпотентен**: повторный запуск ничего не сломает, уже исправленные
ноды он пометит «уже так». Правки вслепую он тоже не делает — нода по id
принимается, только если её текст совпал с `from` или `to`.

## Как добавить правку подписи

Дописать строку в `EDITS` в `code.js`:

```js
{ id: "368:442", from: "← Города и группы", to: "← Города и чаты", where: "Города 368:429 — «Назад»" },
```

Если подпись встречается на нескольких экранах, а править нужно один, добавьте
`in` с номером кадра — поиск ограничится им:

```js
{ id: "", in: "349:580", from: "1 / 6", to: "1 / 8", where: "Все записи — пагинация" },
```

Без `in` такая правка разъехалась бы по всему макету: «1 / 6» стоит ещё в
четырёх кадрах.

`from` нужен не для сверки, а как запасной путь: если id ноды в макете сменился
(например, кадр перерисовали), плагин найдёт её по тексту и скажет об этом в
отчёте. `id` можно оставить пустым — тогда поиск идёт только по тексту; так
заведены кадры `368:*`, которых нет в локальном дампе. Если одна и та же подпись
стоит на нескольких экранах, плагин поправит все.

## Две особенности, на которых легко споткнуться

**Шрифты.** Текст правится посегментно: у ноды может быть несколько шрифтов —
эмодзи почти всегда идёт отдельным сегментом, — и Figma не даст менять символы,
пока каждый не загружен. Если родного шрифта в системе нет, плагин подставит
ближайшего родственника (`Google Sans` → `Google Sans Flex` → `Roboto` →
`Inter`) и напишет об этом в отчёте. В десктопной Figma у владельца макета
родной `Google Sans` обычно на месте, и подмены не происходит.

**Правится только хвост.** Меняется не весь текст, а расходящаяся часть:
общий префикс остаётся вместе со своим стилем. Иначе Figma применила бы к
строке целиком стиль первого символа, и эмодзи утащил бы за собой свой шрифт.
